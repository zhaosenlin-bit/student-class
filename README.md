# 乐启享课件库 —— 本地离线课件库

这是一个**由乐启享创作**的本地课件库：目录、筛选、详情页、预览播放器、
下载打包、离线化、品牌，全部是乐启享自己写的；课件正文取自公开发布 /
开放许可的课件，并按许可要求保留署名（逐条写在 `mirror/*/NOTICE.md`
与目录数据的 `author` / `license` / `sourceUrl` 字段里）。

库里的东西来自两个公开课本站的**游客可见**部分，以及若干开放许可的
开源课堂：MIT 开源物理课、PhET 官方中文版、铜匠实验室、The Physics
Aviary、Blockly Games。取回的方式是**原样托管站点已经发布的前端代码**，
只把站点真正调用的那几十个 API 换成本地替身，所以 3D 场景、交互、
题库、动画都是原件，保真度是 100%。

两个来源已经**合并成一个**：<http://localhost:4173/>，对外的品牌是
**乐启享机器人**（信息取自 [codebn.cn](https://codebn.cn/)）。
站点只有一条线：**看目录 → 在线预览 → 下载**。

## 这一版：旧页面不会再骗人 —— 全库 1426 门逐门在浏览器里点过

上一版给页面加了"自己认出自己旧了"的机制：页面在 `head` 里带一枚构建
标记，服务端把同一枚标记答给 `/api/version`，标记不一样就自己刷新。
这一版把这条机制又修了一遍 —— 原来它自己有个洞。

### 一、有一道闸把旧页面永久关在了外面

刷新之前，页面先问一次"我是不是已经见过这一版了"（`sessionStorage`）。
问题是这道闸只看"服务端现在这一版"，不看"**我**这一版"：

| 页面自称的版本 | 服务端的版本 | sessionStorage 里记着的 | 结果 |
| --- | --- | --- | --- |
| 旧 | 新 | 空 | 刷新 ✓ |
| 旧 | 新 | 记着"新" | **不刷新**，永远停在旧版 ✗ |
| 新 | 新 | 记着"新" | 不刷新 ✓ |

第二行就是有人一直看着 **1154 门**那个页面的原因：它在别的标签页里已经
被刷新过一次，`sessionStorage` 里记下了新版本；这一格旧页面再问一次，
闸门说"这版我见过了"，于是它就一直旧着 —— 而且它自己不会报警，看起来
就像库没修好。

现在这道闸没了。页面拿自己 `head` 里的标记和服务端的标记比：不一致就
刷新，刷新完两者一致，不会来回抖。刷新完的页面也不会再问出第二遍。

### 二、页面被切回前台时，也问一次

原来只有每分钟问一次。后台标签页的定时器会被浏览器压慢，回到前台时往往
还要再等一分钟。现在多挂了 `focus` 和 `visibilitychange` 两个钩子 ——
读者一回到这个标签页，它立刻就知道自己是不是旧了。

### 三、页脚多了一枚版本标记

光是"自己刷新"不够：读者在旧页面上看不到任何提示，只会觉得这库好像
没更新。现在页脚有一行很轻的 **"资源版本 2026-11-20 08:55"**；
服务端那一版比页面上这一版新的时候，这行字变成一个按钮
**"课件库已更新 · 点击刷新"**，点一下就换过来。

`tools/check-lq-build-stamp.mjs` 读这行字，`tools/check-lq-build-reload.mjs`
把页面改成旧版本、把它叫醒，看它会不会自己回来 —— 两样都绿。

### 四、全库 1426 门，在浏览器里逐门点过一遍

这一版把整库重跑了一遍：**1426 门，浏览器里逐门打开、逐门看画面，
1426 门全绿，0 门坏**。上一版留下的 32 个可疑项（39 张实验讲义页里
接回仿真的那批，加上两门没有画布的纯文字课）这一版全部复验通过 ——
讲义页的仿真框画得出来，纯文字课按新判据（有结构、有内容、没有
"找不到"）也算活的。

## 这一版：目录里不再有"打不开的课件" —— 四件真事

上一版交出去的是 1154 门。这一版目录里是 **1426 门**，而且这一版的
重点不在数字变大，在**每一门都真的打得开**。这一版查了四件事。

### 一、1127 条目录里的幽灵条目被清掉了

合并目录一共有 2370 条，但其中 944 条的正文在线上付费墙后面 —— 早先
也把它们列进目录，卡片上写着"免费下载"，点进去却是 404。现在服务端
只把**正文真的在磁盘上**的那些交给前端（`loadXb()` 里一道
`.filter(p => p.localInstalled)`），页面上出现的每一条，点进去都能
预览、能下载。

章节树、课程包、下载清单也跟着改了一遍：它们原来按名字点名某些课，
点名的那些课有的根本没进门。现在每一份清单都按**实际存在的课**重新
过滤，计数器也重新数了一遍 —— 幽灵引用从 128 处降到 **0**。

### 二、货架名不是学科，学段筛选里冒出来的十个"学科"清掉了

上游的精品课包是按货架卖的，包名里带着年级和册次："八年级物理 ·
上下册"、"高中物理合集"、"七年级数学"。这些名字曾经直接当成学科，
于是"学科"筛选里冒出十个不存在的学科，目录树里也冒出
"生物 · 生物 · 生物 · 八年级"这种叠在一起的组名。

现在包名在服务端就被拆开（`LQ_PACKAGE_SUBJECT`）：包名归包名，学科归
学科，年级单独留在 `gradeLabel` 里。学科筛选只剩真的学科，目录树 75 组
标签全部干净。

### 三、简介里最后那几句"售价 39.9 元"拿掉了

有三门课的简介里带着上游货架的话："售价 39.9 元……购买作品或符合平台
会员权益后可继续使用"。本库里每门课都是免费的，也都能下载，这几句话
说的不是这里的事。

`server\lq-shop-copy.mjs` 按句子把它们挑出来去掉 —— 按句子而不是按
整段，因为"无需安装、登录或摄像头"这种话是本库兑现得了的承诺，要
留下；只有谈价钱、谈试用次数、谈会员的那几句走。改完 4 门课的简介，
构建脚本每次重建也会顺手做同一件事。

### 四、体检工具自己认错的两处

## 这一版：还有几门课在转圈 —— 三个真原因，跟资源多不多没关系

上一版把 53 门卡在"正在打开课件…"的课查到了底。这一版顺着"有的分类里
课件加载时失败、图片是裂的"再往里走，又挖出三个原因 —— 前三个都长在
**两门课之间的对话**里，跟课件的文件有没有下全没有关系；后面几节是
资源本身和体检工具自己的毛病。

### 一、课件还没进门，就先问"我可以运行吗"（53 门课一直转圈）

课件正文里带着一道"课堂门禁"：它先问外面那个页面**"我可以运行吗"**，
得到允许才把画面显示出来。

问题是**它问得太早**：外壳先把课件放进页面，再让它开始跑，而门禁那句
问话常常在课件还没进页面时就到了。外壳那时候在页面上找这个框架，
找不到，就没有答。课件等不到答案，屏幕上就一直写着"正在打开课件…"。

现在外壳手里攥着当前这一门课的那一个框架，问话一来，答给谁不会认错。

（还有一处：门禁收到回答以后要认地址。课件被浏览器关在没有"允许同源"
的框里，浏览器给它的地址是空的，所以回答要认"空的"那个地址才算数 ——
认的是"是不是从抱着它的那个页面来的"，这一条没有松。）

### 二、内嵌模块还在用旧家的说话方式（9 门课一直转到超时）

有几门课（空气与氧气、平面镜成像）不是一页，而是**一页套着几页**：外层
页面里塞着几段 base64，点一下才解开成新的页面。

这几段 base64 是文字替换看不见的 —— 正则扫过整个文件，里面留的还是旧
家的名字。旧名字报"我好了"，外壳只认新名字，于是听不见；课件一直等到
25 秒超时，才露出一句"课件未能启动"。

`tools/fix-embed-protocol.mjs` 把 base64 解开、把名字换掉、再装回去
（9 个文件、11 段）。`tools/scan-brand-embed.mjs` 是查这个的。

### 三、没人回答的时候，课件每一毫秒问一次

门禁等不到回答时会自己再问 —— 但间隔算错了，成了**每一毫秒问一次**。
外壳每答一次，页面就多一次往返；门禁自己也在不停地发。整个页面都在忙
一件没有结果的事。

现在这个间隔是 45 秒：够问一次，也不至于把浏览器淹掉。

### 四、体检工具自己开的标签不关（好课被记成坏课）

全库体检开五个标签一起跑，跑完只关了一个。剩下的四个留在浏览器里，一直
开着课件。下一次体检开始时，机器上已经堆着上一轮留下的页面。

这次量到的：浏览器里堆着 **164 个**页面，其中 145 个是上一轮体检留下的。

现在体检跑完把自己开的标签都关掉。

### 五、浏览器最小化的时候，Chrome 会把动画帧掐了

体检用的 Chrome 是最小化着的。Chrome 对看不见的窗口会**掐掉动画帧** ——
课件正是在动画帧里画出第一帧的。掐掉之后，一门本来 2 秒就画完的课要
十几秒才报"我好了"，体检等不及，就记成"没打开"。

`tools/launch-recon-chrome.ps1` 加了三个开关，浏览器不再掐自己的帧。
现在一门课从打开到画出来 **2 秒上下**。

### 体检也不再是"等够了就算"

以前每门课只等一个固定的时间，慢课被当成坏课，快课白等。现在每开一门
课就去听它自己报"我好了"没有：报了立刻看图，马上接下一门；慢课等它
自己，慢到上限还没好才记成没打开。`--wait` 只是上限。

### 六、两门课各差一张图（这就是"图是裂的"）

全库体检跑到最后，只剩两门课在报 404，而且两张图都是**本机压根没有**
的那种缺：

| 课件 | 缺的那张图 |
| --- | --- |
| 费马原理实验 | three.js 自带的那张圆点贴图（`threejs.org/examples/textures/sprites/disc.png`） |
| 最短时间原理实验 | 一张沙地贴图（`Simulation/textures/sand_texture.jfif`） |

这两张图在上游是有地址的，只是地址被改写成本地路径之后，本机那份从来没
被取回来。`tools/fill-courseware-assets.mjs` 现在也认得课件正文里**带
主机名**的那种写法（`/api/program-assets/<id>/_ext/<host>/<path>`），
照着原样把图取回来，两张一共 6 KB。

顺带把几个漏掉的图片后缀补进 Content-Type 表：`.jfif` / `.bmp` /
`.tiff` / `.avif` / `.apng` / `.heic`。以前 `.jfif` 落在
`application/octet-stream` 上，浏览器不认这一种，就会把它当坏图。

### 七、体检工具自己把好课记成坏课

从课件库里点进去这一条路，体检是这么判的：外壳上那层"正在打开课件…"
收起来了，就算打开。

可是**汇总的时候读错了字段** —— 逐门判定时记的是"收起没有"，汇总时读的
是另一个名字，读出来是空；空值取反，每门课都被算成"还在转圈"。

这一版把两边的口径对齐了。体检自己造的结论不算数，所以汇总和逐门判定
必须读同一个字段。

## 这一版：课件点进去打不开、图是裂的 —— 六个真原因

上一版把镜像页面那一层理顺了。这一版顺着"有的分类里课件加载时失败、
图片是裂的"这句话，往**课件正文自己**里走。查出来六个原因，每一个
都不是"资源没下全"那么简单。

### 一、命名空间被当成外链改掉了（3D 课全灭）

`http://www.w3.org/1999/xhtml` 是 **XML 命名空间** —— 它是一个名字，
不是一个地方。浏览器建元素的时候会把它原样交进去："照这个名子的规矩
造一个元素"。

地址重写把凡是认得出的站点地址都换成了本机路径，这一条也换掉了：
`document.createElementNS("…/_ext/www.w3.org/1999/xhtml", "canvas")` 建出
来的元素没有自己的属性，于是 three.js 一开就抛
`Cannot set properties of undefined (setting 'display')`。

凡是加载 three.js 的 3D 课都是这么坏的 —— 画面一片黑，或者干脆不出现。
现在这几个命名空间（XHTML / SVG / MathML / xlink / xml）一律原样留着。

### 二、课堂门禁没人应答（53 门课在课件库里点进去一直转圈）

课件正文里带着一道"课堂门禁"：课件先问外面那个页面**"我可以运行吗"**，
得到允许才把画面显示出来，10 秒没人回答就自己挡住自己。

线上是课堂会话回答这个问题。本地没有课堂 —— 外壳里负责回答的那两个
函数早被清成了空壳，于是这 **53 门**课（在课件库里点进去，屏幕上一直
是"正在打开课件…"）永远等不到答案。

现在两头都松了：外壳会答"可以"，课件自己在本机也不再等 —— 这里本来
就没有课堂，也没有票要买。这 53 门是自制的透镜、镜子、核能、地形、
化学、积木这几组课。

### 三、贴图路径被拼坏（4 门 3D 课）

早先镜像这批实验室课件时，站点名和它后面的目录是用字符串直接拼在
一起的，中间少了一个斜杠：

```
/_ext/vendorPhyc140/texture/     ← 拼坏了
/_ext/vendor/Phyc140/texture/    ← 本来该是这样
```

于是每一张贴图都取不到。`tools/fix-lq-vendor-paths.mjs` 把这一处
改正（8 个文件）；服务器这边也留了一道兜底：万一还有拼成这样的，
斜杠会自己补回去。

### 四、文件的名字和站点上对不上

有的课要 `textures/green-field.jpg`，站点上摆的是 `greenfield.jpg`；
有的要 `bg1.jfif`，站点上是 `bg1.jpg`。现在服务器找文件时，除了原样
的名字，也认"只差一点"的名字：多一个少一个连字符、下划线，扩展名换
一个说法，都算同一张图。

### 五、几个贴图和模型压根没取回来

上一版补文件补的是"镜像页面里嵌着的网页"要的文件，没管课件正文自己
要的。这几个是漏网的：

| 缺的 | 是什么 |
| --- | --- |
| `Phyc240/textures/pos-plane.png`、`neg-plane.png` | 电容器实验的一对极板 |
| `models/rheostat/RHS750.stl` | 惠斯通电桥里的滑动变阻器模型（7.1 MB） |
| `Simulation/textures/green-field.jpg` | 抛体运动实验的草地 |

`tools/fill-courseware-assets.mjs` 读体检报告，照着站点上的样子把它们
取回来，放进课件自己那一族文件夹里。

### 六、体检工具把慢课当成坏课

上一版全库体检每门只等 1500 毫秒。3D 课要建场景、载贴图、算第一帧，
一半的课在这 1500 毫秒里还没画完 —— 于是好课被记成"一片空白"。

现在两条路分开走，各有各的判据：

- `--route direct` 直接开课件地址 —— 看**正文里**有没有裂图、有没有
  取不到的文件。
- `--route app` 从课件库里点进去 —— 看**外壳上那层"正在打开课件…"**
  有没有收起来。收起来了，才算真的打开了。

顺带把"课件自己说它好了没有"也听上了：课件会告诉外壳"我好了"或者
"我起不来"，这两句现在都被记进报告。

### 这一版的口径

## 这一版：分类里那几门打不开的课，逐条查到底

上一版把 1426 门课逐门验过。这一版是顺着"有的分类里课件打不开、
图片是裂的"这句话往里走 —— 课件正文那一层是好的，坏的是**课件正文
里嵌着的那些整页网页**：有几门课是把外面某个站点整站存下来的，那些
页面自己会写图、样式表、兄弟页面，搬过来以后有一半落空了。

### 先修体检工具自己：884 个页面，全是它走错了门

`tools/check-lq-ext-pages.mjs` 是这一版新写的体检工具。第一次跑完，
**884 个页面全部报有问题**。看着像一场灾难，其实是工具把课的编号
写错了：编号是从目录里的文件名拿的，文件名带 `.html`，地址里不带 ——
于是每一次请求都问到了一个不存在的课，页面当然一片空白。

修掉之后再跑，坏掉的页面从 884 个降到 **221 个**。这 221 个是真的，
而且每一个都有名字。

体检工具自己还有两个毛病，一并修了：

- **上一页的账算到下一页头上**。404 是浏览器晚了一步才报出来的，
  记在同一个标签页里，下一页就替它背了。现在浏览器给每一次回答都
  带一个"这是哪一页问的"编号，只算本页的账。
- **只看标签里的地址**。有些地址是脚本在跑的时候才拼出来的，页面
  文字里根本没有。现在也看样式里的 `url()`。

### 真的坏在哪：六处

- **镜像里的页面比原站多了一层目录**。原站上
  `https://www.mathsisfun.com/obtuse.html` 写的是 `../style4.css`，
  意思是"本站根目录下的那个样式表"；搬过来以后 `../` 往上走一层，
  走到了 `_ext/` 就停住了，样式表、脚本、图标全跑到隔壁去了。
  现在服务器把页面里的相对地址**按原站的根目录**重新算一遍，再指回
  本地的那一份。
- **脚本运行时拼出来的根地址**。有些页面在脚本里现拼
  `/images/style/menu.svg`，文字里查不到。浏览器会在请求里说明"我是
  从哪个页面来的"，服务器照着那个页面所属的站点去找 —— 找得到就
  给本机的那一份，找不到就算了，不猜。
- **同一个站自己的绝对地址**。`https://www.mathsisfun.com/x.html`
  这种写法在搬过来的页面里到处都是，有时还写在脚本里

- **页面按"网站根目录"写地址，搬过来以后落空了**。共享库里的页面

  8 张头像收齐取回本机，服务器再把这些图指到本地那一份。

### 缺的东西怎么补

`tools/fill-ext-missing.mjs` 把每个页面写到的地址都算成它该在的位置：

1. 本地有 —— 什么都不做；
2. 本地没有、原站还在 —— 取回来放进共享库；
3. 原站也没有了 —— 就近找一张同名的图顶上；
4. 再没有 —— 放一张空白占位（图片）或一页人话（网页），**不留裂图**。

## 这一版：分类里的课都能打开了，裂掉的图也补齐了

上一版把全库扫了一遍，1426 门课里挑出 40 门有问题。这一版把它们

### 先说清楚一件事：有些"打不开"是假的

有 53 门课带着一道门禁 —— 单独打开它的地址，页面上只会写"请从乐启享

### 真的坏在哪

查下来的原因一共四类：

- **三门化学课的 importmap 指错了地方**。课件里写的是
  `"./courseware/afe-603/…"`，文件其实在 `courseware/b-zone/`、

  死掉。`tools/fix-lq-importmaps.mjs` 改的就是这个。
- **一批物理实验课向网站根目录要文件**（`textures/head.png`、
  `models/dancer/scene.bin`、`textures/steel_texture.jpg` …）。在原站上
  这些文件就放在最外层，搬进本地以后落空了。原站还在，一趟取回来放进
  共享库（`tools/fill-root-assets.mjs`），本机再有人问同一个地址就答得上。
- **贴图名被写成了整条地址**，模型加载器又把路径拼了一遍，于是去找
  `…/Bridge2//api/program-assets/…/_ext/vendor/Phyc140/posx.jpg` 这种
  两头都不对的名字。`tools/fix-lq-loader-paths.mjs` 把名字还原成
  `posx.jpg`，5 门课 65 处。
- **几门课的图和视频上游已经删了**。《简爱》缺 36 张图 10 段声音，

### 扫出来的是真的还是假的，分清楚

体检工具一开始把 264 处报成"缺文件"，其实只有 1 处是真缺。剩下的是

## 这一版：预览滚得到底、每一门都绿灯、上线不卡

这一版修的是三件被反复指出来的事：预览打开后**下面看不到、也滚不动**；
点开某一门课件**报"本地没有安装这份课件"**；以及**部署到线上之后
预览打不开、页面很卡**。

### 预览现在能滚到底

- **预览从页头底下开始，正好占满剩下的地方**。以前预览框从视口下方
  36 像素处开始，而页头是浮在页面上的固定条 —— 于是课件的头一截被
  页头盖住，底一截又够不着。现在这一版把预览放在页头正下方，高度按
  "视口减去页头和预览条"算：顶部不遮、底部不露。
- **控制条钉在页头下面**。预览条用 `position: sticky` 贴在页头下沿，
  往下滚它一直在手边（"收起预览 / 全屏打开"随时点得到）。
  这一条一开始不生效 —— 封面那个 `figure` 上的 `overflow: hidden`
  会把 sticky 变成"贴着那个盒子粘"，于是控制条跟着页面滚走了；
  预览打开时那个裁剪被取消，问题才真正解决。
- **课件比框高的时候，框跟着长**。`lq-preview.js` 量出课件里最靠下的
  那块内容有多高：框就长到那么高（最多四倍），剩下的部分先让课件自己
  滚；课件不肯滚的时候，页面才继续往下延伸。两件事一起做：框够不到的
  地方框变高，框仍然够不到的地方课件内部可以滚，页面也可以滚。
- **打开时量一次，窗口变了再量一次**，所以手机转屏、收起页头之后高度
  都是对的。
- **实测**（1440×900）：预览打开后控制条贴在页头下沿，课件框从页头
  底下铺到窗口底边；页面能滚到最底，课件的底部按钮（Back / Next /
  Replay）都在画面里。（页头后来从 100 像素压到了 58 像素，这里跟着
  一起变 —— 控制条永远是 `top: var(--header-height)`。）

### 每一门课都验过一遍

`tools/check-lq-all-courses.mjs` 把目录里的每一门都取两次：一次当页面看
（`/courseware/<id>`），一次当文件拿（`/api/downloads/prepare` →
`/api/downloads/file/<id>`），并检查内容类型、长度、缺文件提示页和 zip
的文件头。

```
node tools/check-lq-all-courses.mjs --conc 10
```

最近一次全量结果：**1426 门，预览与下载全部通过**（报告在
`recon/scratch/lq-all-courses.json`）。

顺带修掉的两件事：

- **打不开的那几门不再装样子**。服务端遇到没有文件的课程号，回的是一页
  自己的话（"本机还没有这份课件的文件"），不是一行 JSON —— 以前那行
  JSON 会直接印在预览框里，看着像站点坏了。前端也会看这一页的文案，
  顶栏写"这门课件本机还没有文件"，而不是"课件已打开"。
- **拆分成小课、而小课一门都不在的入口，从目录里去掉了**。服务端只保留
  "拆分后至少有一门在本地"的入口（`loadXb()` 里过滤
  `courseReplacements`）。

### 上线之后不卡

- **正文先打包再发**。课件正文、脚本、样式表和目录 JSON 全部压缩后传输：
  一门课从 55 KB 变成 20 KB，目录 JSON 从 1.7 MB 变成 218 KB。
- **文件不重复读、不重复打包**。打包好的正文和下载用的 zip 都留在内存里
  （上限 96 MB / 192 MB），同一门课第二次打开是几毫秒。
- **带上 ETag**。文件没变就回 304，浏览器不用重新下。
- **目录分批画**。目录一次只画 48 张卡片，下面一个"继续加载"按钮，剩下的
  要的时候再画。以前一次性画 1426 张卡，页面又慢又卡。
- **长音频和长模型支持分段读**。以前浏览器要 17 MB 的录音就整个拿，
  现在按 `Range` 段落给（206），可以边下边放、可以拖到中间。
- **实测**：单门课预览 2–21 毫秒，下载 8–41 毫秒（缓存热了以后）；
  目录页首次内容绘制 180 毫秒，课件在框里 398 毫秒就绪。

#### 放到 https 域名下也能用

这一版另外修了两处**只在放到线上才会犯**的毛病 —— 在本机
`http://127.0.0.1:4173` 上怎么测都看不出来，一挂到 https 反向代理
后面就全坏：

- **课件的课堂握手认错了地址**。课件正文里写死了它自己的
  `origin`，服务端以前一律改写成 `http://<Host>`。放在 https 后面时，
  浏览器那边是 `https://站点`，正文里却是 `http://站点`，两边对不上，
  课件就停在"请从乐启享课件库重新打开"那一屏。现在改成照着代理转来的
  协议走（`X-Forwarded-Proto` / `X-Forwarded-Host`）。
- **下载按钮一律 403**。站点的 POST 接口要核对来源地址，老写法要求
  `Origin` 恰好等于 `http://<Host>`，https 下必然对不上，于是每一个
  下载都被挡掉。现在按**主机名**比对，协议不同不算事；跨站请求照样
  挡掉（还要求浏览器先发一个预检，而本服务不放行预检）。

上线时的三个环境变量：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `LQ_HOST` | 监听地址，容器里要 `0.0.0.0` | `127.0.0.1` |
| `LQ_PORT` / `PORT` / `XB_PORT` | 监听端口 | `4173` |
| `LQ_PUBLIC_ORIGIN` | 对外的正式地址（如 `https://study.example.com`） | 不设 |

```powershell
# 本机
node server\server.mjs

# 放到线上（容器 / 反向代理后面）
$env:LQ_HOST = "0.0.0.0"
$env:PORT = "4173"
$env:LQ_PUBLIC_ORIGIN = "https://study.example.com"
node server\server.mjs
```

## 这一版：敏感信息、审计盲区与下载包的真问题

上一版把"别的品牌"清干净了，但审计只扫 HTML，脚本里的话、目录数据
里的话都溜了过去。这一版把审计的覆盖面补全，顺手发现了几个下载包
里的真问题。

### 敏感信息：手机号、地址、统一社会信用代码

"关于我们"弹窗里原本写着两部手机号、办公地址和一行标着"统一社会
信用代码 / 备案号"的备案号；目录数据里的 `support` 字段把同一串
号码当成"联系邮箱"显示。这是个公开仓库，也是一个装在老师电脑上的
本地库，里面不该留下会响到别人手机上的号码。现在：

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| 关于我们弹窗 | 名称 + 简介 + 口号 + **手机号 + 地址 + 备案号** | 名称 + 简介 + 口号 + 官网 codebn.cn |
| 目录数据 `support` | 两部手机号（还标成"联系邮箱"） | 空 |
| README 品牌表 | 电话、地址两行 | 只留名称、口号、备案号、Logo，联系方式指向官网 |

审计工具也跟着长了几只眼睛：

| 工具 | 现在查什么 |
| --- | --- |
| `tools/audit-lq-sensitive.mjs` | 页面 **+ 外壳脚本 + `catalog.json`** 里的手机号、邮箱、微信号、QQ、备案号、统一社会信用代码、客服电话、身份证号 |
| `tools/brand-audit.mjs` | 除了文件，还逐字段查目录数据里**会被渲染出来**的那些（标题、简介、标签、作者、模块、章节目录） |
| `tools/build-leqixiang.mjs` | 构建结束前再扫一遍外壳，命中就**直接构建失败**（不是发出去再改） |

手机号规则也修了：以前一个 11 位数字挨着字母就算号码，于是
`b017b74d18533067124e350d…` 这种封面哈希被当成电话报了 200 多处；

### 下载包里三个真问题

下载的 zip 是"老师拿到就能用"的东西，这一版把三处真问题找了出来：

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 站点根目录的资源没进包 | 3D 仿真课引用 `../models/pencil/scene.gltf`，压缩包里没有，打开就是空白 | 建包时把**站点根**里被引用的文件一起收进 `assets/`，并把名字指到包内 |
| 3D 模型只有场景、没有数据 | `scene.gltf` 拿到了，`scene.bin` 和贴图没镜像，控制台报 `Failed to load buffer "scene.bin"` | 新增 `tools/fetch-3jcn-model-parts.mjs`，把 19 个缺件从原站取回（`scene.bin`、法线贴图、粗糙度贴图……） |
| 课件还在向平台问授权 | 用启动器（本机地址）打开时，课件问 `/api/program-file/verify-access`，本机没有这个接口，于是整页变成"课件启动失败" | 授权守卫在包内一律由包自己回答（`data:` 里的本地"是"），六种写法都覆盖 |

还有一处口径问题：`tools/check-lq-zip-offline.mjs` 以前把"没有
canvas"当成坏页，但滑块式课件本来就不用 canvas；它也只看顶层页面，
而章节课把内容放在自己的 frame 里。两处都按"老师实际看到的东西"
改了：读 frame 里的文档，文字够长也算打开。

### 审计的两个盲区（这一版补上）

静态审计读的是磁盘上的文件，读者看到的是浏览器里画出来的东西。这两样
东西并不总是一回事，这一版把两个盲区堵上了。

**盲区一：脚本里会写到屏幕上的字。** `brand-audit.mjs` 原来把 `.js`
和 `.mjs` 当成"代码"，只记一笔不算数。可是模块里写着
`` `<div class="cl-brand"><small>某某教育 · 某某工坊</small>` ``
这样的字符串时，浏览器会把它画到屏幕上 —— 读者读得到，审计却看不见。
现在脚本按"会显示的字"再扫一遍（课程内部的名字 `phet-`、`lab-`、
`afe-` 这些是内部编号，不算名字，另有白名单）。审计文件数也从 2493
涨到 2533。

**盲区二：课件旁边的说明文件。** 一门钢琴课把 24 首曲子的来源写在自己
旁边的 `repertoire/attribution.txt` 里，链接由课件目录指向它。`.txt`
原来不在扫描范围里，于是那 6 行署名躲过了所有检查。现在 `.txt` / `.md`
也进扫描，并且 `tools/brand-scrub.mjs` 会把这类署名里的别家名字换成
乐启享（这些编曲是 CC0，本来也不要求署名）。

**再加一层：渲染后的审计。** 新工具 `tools/audit-lq-rendered.mjs`
用真浏览器打开目录页和九个来源各一门课的详情页，把**顶层文档和每一层
 iframe 里**的可见文字收起来再扫一遍，同时记录这一路请求真正联系过
哪些域名。当前结果：可见文字里没有别家品牌，没有敏感信息；对外请求
一个也没有，全部落在本机。

**构建期也加了闸门。** `tools/build-leqixiang.mjs` 在写完目录之后会
再扫一遍交付的课件正文（2219 个文件）、外壳和目录数据里会被渲染出来
的字段，命中别家名字就直接构建失败 —— 不是发出去再改。

## 这一版：127 门 PhET 全部重做 —— 之前它们其实一台都没跑起来

上一版交出去的时候，127 门 PhET 交互模拟在目录里都点得开、封面也
好看，但**打开以后每一门都停在加载页**：加载动画转圈，模拟本身不
出现。本轮从头查了一遍，发现是三个 bug 叠在一起，每一个都足以让
整个模拟起不来：

| 症状 | 真正的原因 | 怎么修的 |
| --- | --- | --- |
| 模拟永远停在加载页 | 清洗脚本把仿真里的外链改写成本地地址时**把引号一起吃掉了** —— `"https://…/"+i.locale` 变成裸的 `/license.html`，浏览器把它读成正则字面量，整段 2 MB 的程序直接语法报错 | 改写时必须带上原来的引号 |
| 同一个文件还有第二个语法错 | 有些地址写在模板字符串里，模板里**还嵌着模板**（`` `…${encodeURIComponent(`${…}`)}` ``），按第一个反引号截断就把表达式劈成两半 | 加了一个能走平衡 `${}` 和嵌套反引号的模板扫描器（`templateEnd` / `rewriteTemplates`） |
| 右下角还是别家的字标 | 字标是两张 273×108 的 PNG，直接写在程序里，两张的内容还一样 | 按尺寸认出这两张图，换成乐启享字标（`tools/make-wordmark.mjs` 现场渲染透明底 PNG） |

修完之后，**127 门重新取回、重新清洗、重新构建**，每门都真的跑起来
了：程序自己解析出来（`vm.Script`，2693 段脚本 0 报错），页面里

### 章节通道的协议 —— 拿到 `1387` 的那一手

`1387`（音乐和弦实验室：3D 钢琴与互动课堂）是 2026-11-15 才上线的新作品，
目录接口上带着 `reviewed_public_runtime` 标记：它走的是**章节公开课**那条
通道，但只有一个入口。把这套协议摸清之后，章节课就不用再猜了：

| 步骤 | 请求 | 拿到什么 |
| --- | --- | --- |
| 1. 开会话 | `POST /api/reviewed-course-session/<id>/open` | 会话 id、descriptor、允许进入的 entry 列表 |
| 2. 挂载 | `POST /api/reviewed-course-session/session/<sid>/mount {entry}` | 挂载前缀，形如 `/api/reviewed-course-assets/<sid>/<56位hex>/` |
| 3. 取正文 | 浏览器沙箱 frame 里读 `outerHTML` | 章节文档（**node 直接 fetch 必然 403**，只能让浏览器加载后从 frame 里读） |
| 4. 取素材 | `GET <prefix><相对路径>` | 素材文件（**必须跟随重定向**，`redirect:'manual'` 会全部 404 / 403） |
| 5. 复用会话 | `POST /api/reviewed-course-session/session/<sid>/resume {programId}` | 不消耗试看额度的续用 |

第 4 条踩过坑：素材地址是 302 跳到 CDN 的，手工挡掉重定向就什么都拿不到。
第 3 条也是踩过坑的：文档有防盗链，只有浏览器 frame 里的 `outerHTML` 拿得到。

**1387 落地了 119 个文件**：8 个钢琴音色 mp3、30 首 MIDI 曲谱（每首一个
`.mid.json`）、Next.js 分块（含 `piano-world-C_Yb7aio.js`）、字体、
`_course_runtime/*` 全套运行时、许可文件。封面和 4 张介绍图也镜像了。

#### 握手要用对顺序，否则课件一片黑

章节课的外壳里那个 iframe，和里面的章节文档是靠一次 `postMessage` 握手
连起来的。握手只有一次机会：**桥接层把第一次 `load` 事件用掉，就只认它**。

页面里那个 iframe 解析时就在文档里、没有 `src`，于是它的第一次 `load`
事件是 `about:blank` —— 这次机会被空文档用掉了，真正的章节文档再也不会
被放进来，屏幕就一直黑着。线上没这问题，因为它把 iframe 放在页面外面建好、
接上宿主、再指向章节、最后才挂进 DOM。

本地现在照线上这个顺序做（`tools\lq-reviewed-host.js` 的 `freshFrame()`）：

```js
const element = document.createElement('iframe');  // 不在文档里，没有 load 事件
host = registerFrame(window, element, options);    // 先接上宿主
element.src = url;                                 // 再指向章节
stage.replaceChildren(element);                    // 最后才挂进 DOM
```

另外，生成外壳的活儿现在只由 `tools\rebuild-chapter-index.mjs` 干 ——
`tools\finalize-afe-chapters.mjs` 只负责把章节文档里的路径改成本地地址，
然后把生成外壳这一步**委托**过去。早先两个工具各写各的，外壳被后者覆盖，
带运行时的宿主被抹掉，章节课本地就跑不起来了。

### 下载

上游站点二的作品是"一份正文 + 一个素材目录"，下载时打成一个 zip；
上游站点一的课件是单文件 html，直接给。解压后双击 `afe-xxx.html` 就能
在本机浏览器里用，素材路径全部是相对路径。

zip 里的路径是唯一的：同一份文件（three.js 最常见）既在课件自己的
目录里、又在共享库里时，只写一份进去，不会出现两个同名条目。另外把
早先抓取时落在 `assets\api\program-assets\` 下的 94 个空壳（平台的
"加载中"跳转页，不是素材）清掉了，它们只会让压缩包多出无用的条目。

**共享库以前是漏的，现在补上了。** 打包器要收集课件用到的公共库
（three.js、GSAP、Mediapipe、Google Fonts、MathJax……），可它读的是
改写**之前**的地址，而地址在更早一步就被换成 `./assets/_ext/…` 了，
于是那份清单永远是空的 —— 476 门课里 149 门用 Google Fonts、46 门用
jsdelivr，下载下来的包打开全是兜底字体，three.js 直接不加载。
现在按改写**之后**的地址来收，公共库跟着包走。

Google Fonts 那份样式表是"所有字族合并成一份"的（1.7 MB），这里改成
按课件点名的那几个字族裁剪后再给；CJK 字族带一百多块 unicode-range
分片，塞进每个包会多出几兆，所以下载包里留给系统字体 —— 线上预览仍然
是完整的。

### 占位件 —— 拿不到的那几样，不让课因此废掉

`616`（经典常谈互动立体书）原来在本地是**打不开的**：它启动时把贴图
和题库放在同一个 `Promise.all` 里

就抛，立体书根本没被建起来。页面照样有回应，看起来像打开了，其实里面
什么都没有。

### 本地身份

原站每个交互动作都挂在微信登录态后面（`localStorage.aiedu_token`），
没有登录态前端根本不会去请求课件地址。本地副本没有账号体系，所以服务端
会签发一个**本地身份**（`Bearer local-…`），页面加载时自动写入
`localStorage`，界面右上角显示"本地用户"。

这个身份只解锁**界面**，不解锁任何内容：作品正文仍然必须是你自己下载
回来、放进 `courseware\` 目录的文件才会出现。没有本地文件时，播放器会
明确提示"本地未安装这份课件：请把在官网下载到的 HTML 放进
mirror/aifunengjiaoyu/courseware/<id>.html"。

### 本地装了的课件按"已拥有"处理 —— 和站 1 一样

站 1 的做法是：本地装了的课件在目录里直接标成
`owned / accessible / canDownload`，点开就能玩、能存下来，不问你要不要
买。站 2 原本还停在"购买 / 免费试用"的按钮上，看着别扭。

现在改成一样：`/api/user/purchases` 返回本地 `courseware\` 目录里实际
存在的作品号，前端读到 `purchasedIds` 之后就会把这一份显示成

## 这个仓库里装了什么

仓库地址：<https://github.com/zhaosenlin-bit/student-class>

克隆下来之后，`node server/server.mjs` 就能跑 —— 服务端只依赖 Node
自带模块，不需要 `npm install`。

根目录是从 `server/server.mjs` 自己的位置推出来的，所以仓库放在哪儿都
能跑；`tools/` 下的脚本同理。想把镜像放到别的盘，设 `LQ_ROOT` 就行：

```powershell
$env:LQ_ROOT = 'D:\courseware-library'
node server/server.mjs
```

| 目录 | 内容 |
| --- | --- |
| `server/` | 本地服务（一个文件，Node 自带模块，无依赖） |
| `mirror/` | 镜像下来的全部站点内容：合并站、乐启享站点外壳、两个原站、课件正文与素材 |
| `tools/` | 镜像、重建、验收这一整套脚本（不含本机装的工具链） |
| `recon/` | 逆向过程的报告与证据（markdown / json） |
| `craft-anything/` | Rust 写的静态分析工具箱源码（编译产物 `target/` 不入库） |
| `rea/` | 观测工具 REA 的源码 |

没有入库的东西，都是"哪台机器上都能重新生成"的：

- 工具链（`tools/node24`、`tools/mingw64`、`tools/mingw-binutils`、
  `tools/.cache`）—— 装一次就好；
- `craft-anything/target/`（1.1 GB 编译产物）—— `cargo build --release`
  或者 `tools/build-craft-anything.ps1` 能重造；
- 抓取用的浏览器 profile（`tools/chrome-*`）；
- `recon/captures/`、`recon/scratch/` 里的一次性产物，和所有凭据
  （`*.token` / `*.cookie` / `.env`）。

三件值得单独说的事：

1. **`rea-src/` 是 `rea/` 的逐字节副本**，所以只跟踪了 `rea/`。两个目录
   都完整保留在本机（`C:\kaifa\xiaobai-class\`），只是 `rea-src/` 不入
   仓库。
2. **三个上游项目的 `.git` 目录搬到了 `C:\kaifa\_vendored-git-backup\`**，
   历史一个字没少，但不进仓库 —— 否则 git 会把整个目录当成子仓库，
   源码反而进不去。
3. **镜像里删掉了 3 个文件名末尾带点的文件**（`issues/21559.`、
   `issues/21819.`、`wiki/Three.js-Shading-Language}.`）。它们是爬虫
   从 three.js 的 JS 注释里把 URL 连同句末标点一起抓下来的产物 ——
   注释里的链接浏览器永远不会去请求，而且这种文件名在 Windows 上根
   本打不开、git 也索引不了。全仓再扫一遍，末尾带点 / 带空格的名字
   已经是 0。

两个脚本都只做**线上公开的握手**（取 access-token → 换正文 URL → 下载），
拿不到就如实记一条 `refused`，不会去绕任何鉴权。拉下来的正文按站点约定
落盘：

| 站点 | 落盘位置 |
| --- | --- |
| 上游站点二 | `mirror\aifunengjiaoyu\courseware\{作品号}.html`（附件在同名 `.assets\` 目录） |
| 上游站点一 | `mirror\xbjiaoyu\courseware\{产品id}.html` |

合法拿到文件之后的本地安装方式：

1. 在官网正常登录、购买或试用，下载课件 HTML。
2. 放到 `mirror\aifunengjiaoyu\courseware\{作品id}.html`
   （id 就是目录里那一项的数字，例如 `754.html` 对应"长征"）。
3. 重启服务。作品卡片上的"▶ 在线预览"就会指向
   `http://localhost:4173/courseware/754.html`，完全离线运行。

助手页的**AI 生成**功能依赖云端模型，本地副本把它标为只读（面板上会
写明"本地离线副本：课件创作依赖云端模型，本地不提供"）。其余所有界面
交互都还在。

## 本地服务做了哪些改动

| 位置 | 改动 | 原因 |
| --- | --- | --- |
| `/courseware/{id}.html` | 把课件里写死的 `"origin":"https://xbjiaoyu.com"` 改成本地 origin | 课件会和父页面做课堂握手，origin 不匹配就一直是黑屏 |
| `index.html` | 去掉 `content-guard.js`（防开发者工具 / 右键另存） | 个人本地副本，这段会挡住浏览器的调试能力 |
| `/play/<id>.html` | 去掉页面里的反调试按键拦截 | 同上 |
| `/api/catalog` | 全部条目按"免费"渲染，但只有本地真的有的才标记可玩 | 关掉商业化，又不谎报可用性 |
| `/api/launch/{id}` | 无本地文件时返回 410，和原站对付付费课件的措辞一致 | 保持行为一致 |
| `/api/*`（站 2） | 按游客身份逐条对齐线上返回码（401 / 404 / `{"success":false}`） | 让前端在离线下走和线上一模一样的分支 |
| `/api/*`（站 2）· 未知路径 | 照抄 Express 那页 `Cannot GET /api/xxx` 的 HTML | 线上未知路径回的是 HTML，前端 `r.json()` 会抛异常，两边得一样 |
| `/api/*`（站 1）· POST | 校验 `Origin` + `X-Requested-With: studio`，缺一就是 403 | 线上就是这么挡跨站 POST 的，本地照抄 |
| 静态文件 · 非 GET | 405 `{"error":"不支持此操作"}`（站 1）/ 404 HTML（站 2） | 线上静态资源只收 GET/HEAD |
| 未知路径 · GET | 404 `{"error":"未找到"}`（站 1）/ 404 HTML（站 2） | 站 1 用 hash 路由，线上没有 SPA 兜底，本地也不该有 |
| `/api/programs/<id>/access-token` | 返回本地 token，指向 `courseware/<id>.html` | 这是前端真正用来打开课件正文的握手接口 |
| `/api/programs/<id>/camera-launch` | 摄像头类课件返回本地播放地址 | AR / 体感类课件在原站走的是这条分支 |
| `/prod/uploads/*` | 直接吐镜像下来的 CDN 文件 | 前端所有图片和演示视频都指向这里 |
| `/cdn-cgi/*` | 204 | Cloudflare 埋点，本地没有意义 |

镜像出来的课件文件本身**一个字节都没改**，全部保持原站发布的样子，
改写只发生在服务端返回的那一刻。

## 接口对得上吗 —— 三层交叉验证

光"页面能打开"不算复刻到位。前端拿到 200 还是 401、走 JSON 还是走
Express 的 404 页面，会进入完全不同的分支，所以接口要按**方法**和
**响应体**都对上。这件事分三步做，每一步都能独立复跑。

### 第一步：用 craft-anything 读代码

`js_app_map` 静态解析镜像下来的 bundle，列出它可能调用的每一个接口。
整目录一起解析比只解析单个入口包更全：

```powershell
.\craft-anything\target\release\craft-anything-cli.exe --deep js_app_map `
  --input-path "C:\kaifa\xiaobai-class\mirror\aifunengjiaoyu\assets" `
  --output-format json > recon\craft-js-app-map-afe-all.json
```

站 2 的 27 个脚本合起来读出 **61 个接口路径**（其中 21 条带明文
`/api/` 前缀，其余被字符串表混淆）；站 1 的 31 个脚本读出 5 个。
单看入口包时只能读出 54 个和 4 个 —— 剩下的在按需加载的子脚本里。

### 第二步：拿本地和线上逐条对

```powershell
# 从 bundle 清单出发，GET/POST 各比一次
node tools\crosscheck-api-surface.mjs

# 把游客态的接口按方法逐条对
node tools\compare-guest-responses.mjs

# 连响应体一起比（状态码 + Content-Type + 正文）
node tools\compare-response-bodies.mjs
```

第三个工具是最较真的那个：它把**正文**也比一遍。这一步挖出了几个只看
状态码看不见的差别 —— 线上 Express 对它不认识的路径（以及用错方法的
已知路径）回的是一页 HTML：

```html
<!DOCTYPE html>
<html lang="en">
...
<pre>Cannot GET /api/inquiry</pre>
```

本地原来回的是一段 JSON。前端 `await r.json()` 在线上会抛异常、在本地
却能解析出对象，两边走的分支因此并不相同。现在本地也照抄这一页 HTML，
连 `<pre>` 里的路径都一致。

现在的结果：

| 检查 | 范围 | 结果 |
| --- | --- | --- |
| `crosscheck-api-surface` | 17 条明文接口 × GET/POST = 34 条 | **34 条全部与线上一致** |
| `compare-guest-responses` | 29 个游客接口 × 2 方法 = 58 条 | **58 条全部与线上一致** |
| `compare-response-bodies` | 68 个接口 × 2 方法 = 136 条 | **129 条逐字节一致**，另外 7 条是下面列出的有意差异 |
| `compare-afe-premium` | 精品课 29 条接口 + 静态资源 | **29 条全部与线上一致** |

### 第三步：站 1 的 POST 有一道门槛

站 1 的前端在 POST 时会带上自己的 `X-Requested-With: studio` 和
同源 `Origin`。线上没有这两样就直接 **403 请求来源不匹配**，连路由都
不看。这道门槛是逐个请求试出来的（`tools\probe-xb-all-paths.mjs` 记着
40 个接口 × 两种方法的线上答案）。本地照抄了这条规则，所以：

- 浏览器发起的 POST 一律正常；
- 从别的页面（或者脚本）硬发一个 POST，会得到和线上一样的 403。

### 对齐过程中改掉的那些地方

- `GET /api/programs/click`、`GET /api/programs/ratings` 线上是 **401**，
  之前本地一律返回 200；
- `GET /api/programs/sort-by-uses` 线上是 **405**（只收 POST）；
- `POST /api/programs`、`POST /api/premium/capabilities` 线上是 **405 / 404**，
  本地之前用 GET 的逻辑把它们也答了；
- `POST /api/points/balance`、`POST /api/premium/access`、`POST /api/trials`
  线上没有这个路由（404），本地之前被当成 GET 处理；
- `GET /api/creator/*`、`GET /api/user/update` 等线上是 404；
- 站 1 的 `/api/classroom/release` 线上是 **410**（没有课堂租约可退），
  本地之前回 200；
- `POST /api/auth/check-scan`、`POST /api/captcha-token` 线上只收 POST，
  现在本地也按方法区分（captcha token 同样是 16 位十六进制）；
- 站 2 的 `/api/runtime-status` 只存在于 `/tuxiaoling/` 命名空间下，
  顶层那条线上是 404；`/tuxiaoling/api/materials` 只有 POST 是 401，
  GET 是 404 —— 本地现在也把这两个命名空间分开处理；
- `GET /api/premium/access` 线上回 `{"error":"login_required"}`，
  本地原来写的是"请先登录"，现在改成和线上一样的字面量；
- 站 1 的未知路径线上是 **404 {"error":"未找到"}**（不是 SPA 兜底），
  静态文件用 POST 请求线上是 **405 {"error":"不支持此操作"}**；
- `/course-compat/long-march-save-policy.json` 是运行时才会去取的配置，
  之前漏了，本地现在也镜像了一份（线上 1062 字节）。

### 有意保留的本地差异

这些地方本地和线上**故意**不一样，都是"商业机制不需要"那一头：

| 位置 | 线上 | 本地 | 为什么 |
| --- | --- | --- | --- |
| `/api/premium/capabilities` | `{"enabled":true,"uploadsEnabled":true,...}` | `{"enabled":false,"uploadsEnabled":false,"playbackEnabled":true}` | 上传和投稿在本地关掉，前端因此不会把用不了的入口摆出来 |
| `/api/get-qrcode` | 微信扫码登录二维码 | "本地离线副本已自动使用本地身份" | 本地没有账号体系 |
| `/api/auth/verify`、`/api/programs/{id}`、`/api/programs/{id}/access-token` | 游客 401 | 本地身份 / 本地数据 | 让目录、详情弹窗和"立即使用"在离线时能走通 |
| `/api/library`、`/api/creator`（GET） | 401 请先登录 | 空列表（本地已安装的课件） | 同上：页面渲染得出来，而不是撞到登录墙 |
| `/api/downloads/prepare`（POST） | 401 | 交出本地镜像的那份课件 | 本地没有"下载"这个动作，文件本来就在机器上 |
| `/courseware/{id}.html` | 403 请从课件页面重新进入课堂 | 直接给文件 | 线上要课堂票据，本地没有票据系统 |
| `/api/programs` | 商品有价格 | 价格记为 0 | 商业化关掉，但不谎报可用性 |
| `/api/catalog`（站 1） | 付费课要买 | 全部按"免费"渲染 | 同上 |
| `/api/auth/phone/status`（站 1） | 开启手机号登录 | `enabled:false` | 本地不登录，也不该弹手机号验证码 |
| `/api/captcha-token` | 每次一个随机 token | 每次一个随机 token | 两边都是 16 位十六进制，只有值不同 |

状态码在这些地方仍然一致，差别只在响应体。

## 镜像到底忠不忠实 —— 两个项目合起来验

光是"页面能打开"也证明不了镜像忠实：万一某个脚本被改写过，界面照样
能渲染，只是行为和原站不一样。所以这里让 **REA** 和 **craft-anything**
各管一端，在同一件事上对上：

| | 负责什么 | 怎么做的 |
| --- | --- | --- |
| REA | **运行时**：浏览器真正加载了什么 | 抓本地页面的网络事件，连响应体字节一起留下来 |
| craft-anything | **静态**：这个 bundle 里到底有什么 | `js_app_map` 逐个模块算出 sha256 |

流程是这样的：

1. REA 打开 `http://localhost:4173/`（合并站）与两个原站镜像页，
   把每个脚本请求的**响应体**都留下来；
2. `tools\match-runtime-scripts.mjs` 对这些响应体算 sha256，
   同时和本地镜像文件的 sha256 对一遍；
3. 把这份清单交给 craft-anything 的 `js_runtime_code_match`，
   和静态图里的模块逐个比 digest。

结果：

| 站点 | 运行时脚本 | 静态模块 | digest 命中 | 镜像与响应体不一致 |
| --- | --- | --- | --- | --- |
| 站 1 | 62 | 30 | **30 / 30** | **0** |
| 站 2 | 21 | 21 | **21 / 21** | **0** |

也就是说：**浏览器拿到的每一个字节，都和镜像目录里的文件一模一样**，
而静态分析读到的每一个模块，也都在运行时被原样加载过。

站 2 还有 4 个模块（`admin-large/runtime/public-lease.mjs`、
两个长征播放宿主、`vendor/html2canvas.min.js`）在浏览页没被加载 —— 这
是正常的，html2canvas 是导出图片时才按需加载的，另外三个属于管理端和
播放页，游客页面不会打开。

```powershell
# 1. 抓本地运行时（响应体要带上）
node C:\Users\Administrator\AppData\Roaming\npm\node_modules\rea-agents\scripts\rea.mjs `
  capture-browser-scenario recon\scenario-local-afe-runtime.json --json `
  > recon\captures\local-afe-runtime.json

# 2. 算哈希、核对镜像
node tools\match-runtime-scripts.mjs

# 3. 交给 craft-anything 做静态↔运行时比对
node tools\craft-runtime-match.mjs
.\craft-anything\target\release\craft-anything-cli.exe --deep `
  --project recon\craft js_runtime_code_match `
  --json "@recon\craft-runtime-match-aifunengjiaoyu.params.json"
```

craft-anything 的调查报告在 `recon\craft-report.md`，brief、四条结论和
证据账都记在 `recon\craft\` 里。

### craft-anything —— 静态分析与报告

`craft-anything` 是 Rust 写的逆向 / 重建工具箱，本复刻用它做**读代码**
这一环：把混淆的前端 bundle 拆开、把 API 契约和运行时行为写成报告，
让"原站到底调了哪些接口"有据可查，而不是靠猜。

常用命令：

```powershell

# 列出这个工具箱能用哪些能力

  ..\mirror\aifunengjiaoyu\assets\assets\app.17e3fb394175.min.js

# 在项目账本里留下 brief、结论和证据（这一步要带 --deep 和 --project）
.\target\release\craft-anything-cli.exe --deep --project ..\recon\craft `
  core_brief_write --question "..." --purpose "..." --done-when "..."
.\target\release\craft-anything-cli.exe --deep --project ..\recon\craft `
```

现在 `recon\craft-report.md` 里是一份完整的调查档案：一句提问、一段
目的、六条结论，每条都挂着证据 id，末尾是 10 条记录的证据账。

`rebuild` 子命令（让 agent 重建一个网站）是给"从零写"用的；本复刻走的是
**原样托管 + API 替身**的路子，所以没有用它 —— 界面既然能拿到原件，
重画只会更差。

#### 在这台机器上把它编出来

默认的 windows-gnu Rust 工具链在这台机器上还差三样东西，
`tools\build-craft-anything.ps1` 已经把它们补齐了：

| 缺什么 | 为什么需要 | 怎么补的 |
| --- | --- | --- |
| `dlltool.exe` 能找到的 `as.exe` | `windows-sys` 用 `raw-dylib`，要 dlltool 生成导入库，而 dlltool 会去调汇编器 | 从 MSYS2 镜像取 mingw-w64 binutils，把 `as.exe` 放到 rustc 的 sysroot 旁边 |
| 一个能用的 C 编译器 | `ring` 编译 C 代码，cc-rs 找不到 gcc 就直接失败 | 从同一镜像取完整的 mingw-w64 GCC 16.2 工具链 |
| crates 镜像 | crates.io 直连超时；SJTU 的索引又落后于 `Cargo.lock` | 换成 rsproxy.cn 的稀疏索引 |

```powershell
# 一次性装好工具链（binutils + gcc，缓存放在 tools\.cache）
node tools\install-mingw-binutils.mjs
node tools\install-mingw64-toolchain.mjs

# 之后就能直接编译
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-craft-anything.ps1
```

## 边界说明

- 镜像范围 = 站点**公开发布**的内容 + 你自己有权访问的内容。
- 付费正文不破解、不绕过鉴权；未授权的部分在本地就明确显示为不可用。

```powershell
# 站 2：微信扫一下码（工具每分钟自动刷新二维码）
node tools/afe-login-api.mjs
# 扫完就会写出 recon\scratch\afe-token.txt，然后：
node tools/pull-afe-courseware.mjs --token (Get-Content recon\scratch\afe-token.txt)

# 站 1：线上只收手机号+短信验证码（账号密码登录已被关掉，
# 返回 403「请使用手机号验证码登录」），拖动验证码不好自动过，
# 所以在浏览器里手动登一次，再把会话拿走：
node tools/xb-login-cookie.mjs
node tools/pull-xb-courseware.mjs --cookie (Get-Content recon\scratch\xb-cookie.txt)
```
