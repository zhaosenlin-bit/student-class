# 乐启享课件库 · 部署说明

课件库是纯静态的，服务器上不放任何课件文件，全部放在对象存储上，
官网的 nginx 只做转发。访问地址：

    https://codebn.cn/leqixiang/

---

## 一、东西放在哪

| 项目 | 值 |
| --- | --- |
| 对象存储桶 | `teaching-platform-files` |
| 区域 | `oss-cn-hangzhou`（杭州） |
| 桶内前缀 | `leqixiang/` |
| 文件数量 | 16964 个 |
| 总体积 | 约 3.7 GB（磁盘上实际占 3.3 GB） |
| 权限 | 桶里的对象是公开可读的，别人直接就能打开 |

这个前缀是给课件库单独用的，和同一个桶里别的系统
（`common/`、`course/`、`python/`、`student-work/` 等）各走各的，互不掺和。

**先确认对象存储是通的**：浏览器直接打开下面这个地址，能看到课件库首页就算好了。

    https://teaching-platform-files.oss-cn-hangzhou.aliyuncs.com/leqixiang/index.html

打不开的话，先去对象存储的控制台确认「读写权限 ACL」是「公共读」，
或者确认这个域名没有被 CDN / 防盗链拦住。

## 二、改 nginx（宝塔面板）

### 1. 打开配置文件

宝塔面板 → **网站** → 找到 **codebn.cn** → 点右侧的 **配置文件**。

里面就是你贴过来的那份 `server { ... }`。我们要往里面加东西。

### 2. 粘进去

把 `deploy/nginx-oss.conf` 这个文件里的**全部内容**，原样粘贴到
`server { ... }` 里面。

**放在哪里**：放在 `server { ... }` 里面、`location / { ... }` 之前或之后都行。
只要在 `server` 里面、不要放到 `http { ... }` 里面就行。

粘贴完之后，`server` 段里应该多出这三段：

```nginx
    location = /leqixiang {
        return 301 /leqixiang/;
    }

    location = /leqixiang/ {
        proxy_pass https://teaching-platform-files.oss-cn-hangzhou.aliyuncs.com/leqixiang/index.html;
        ...
    }

    location ^~ /leqixiang/ {
        proxy_pass https://teaching-platform-files.oss-cn-hangzhou.aliyuncs.com;
        ...
    }
```

### 3. 有两个地方要留意

**（1）`^~` 那个符号不能去掉。**

你的配置里有这两条正则：

```nginx
location ~* .html$ { ... try_files $uri =404; }
location ~* .(css|js|mjs|png|jpg|jpeg|gif|webp|avif|svg|ico|woff|woff2|ttf|mp4|webm)$ { ... try_files $uri =404; }
```

正则 location 的优先级比普通前缀 location 高。这两条会**先**把课件里的
网页、脚本、样式、图片抢走，转成去服务器磁盘上找——服务器上没有这些
文件，于是全部 404。加了 `^~` 之后，这一段不再走正则。

实测过：去掉 `^~`，13 个抽样地址里坏掉 10 个。

**（2）`proxy_pass` 后面不要带路径。**

```nginx
proxy_pass https://teaching-platform-files.oss-cn-hangzhou.aliyuncs.com;
```

就这样，结尾**没有斜杠**，也**没有** `/leqixiang`。

浏览器发来的地址原样转给对象存储，课件里那些中文、空格、表情符号的
文件名才对得上。如果写成 `.../leqixiang/` 或者 `.../leqixiang-courseware/`，
nginx 会先把地址解开再转过去，名字里的加号会被对象存储当成空格，
有几个文件就取不到了。

### 4. 检查 rewrite 文件

你的配置里有这一行：

```nginx
include /www/server/panel/vhost/rewrite/codebn.cn.conf;
```

这个文件的内容我们看不到。**请打开看一眼**，如果里面有 `location` 开头的
段落、或者有 `rewrite` 规则会拦下 `/leqixiang/`，就把它挪到我们那三段的
后面（或者去掉对课件库的影响），否则课件库会被抢走。

一般这个文件里只有宝塔自动生成的伪静态规则（`try_files $uri $uri/ /index.php`），
不影响 `/leqixiang/`。

### 5. 保存并重载

点 **保存**。宝塔保存时会自动做一次语法检查，显示「配置文件检查通过」再重载。

也可以 SSH 上去自己检查一遍：

```bash
/www/server/nginx/sbin/nginx -t
```

看到 `syntax is ok` 和 `test is successful` 再重载：

```bash
/www/server/nginx/sbin/nginx -s reload
```

或者在宝塔里点 **服务 → 重载**。

## 三、验收

### 1. 浏览器里打开

    https://codebn.cn/leqixiang/

应该看到课件库首页：1450 份课件、左侧章节目录、封面图、搜索框、筛选。

### 2. 点进任意一门课件

点「在线预览」，课件要能真的动起来、能拖参数、能切视图。

### 3. 命令行抽查（可选）

```bash
curl -I https://codebn.cn/leqixiang/
curl -I https://codebn.cn/leqixiang/catalog.json
curl -I https://codebn.cn/leqixiang/brand/brand-mark.png
curl -I https://codebn.cn/leqixiang/courseware/lq-100/index.html
```

四个都应该是 `200`，而且 `Content-Type` 分别是
`text/html`、`application/json`、`image/png`、`text/html`。

**特别注意**：返回里不能有 `Content-Disposition: attachment`。
有的话说明「强制下载」的头没摘掉，浏览器会把网页当文件下载。

再抽查一张样式表，类型必须对：

```bash
curl -I https://codebn.cn/leqixiang/shared/~71f475aa/assets/_ext/fonts.googleapis.com/css2.css
```

`Content-Type` 要是 `text/css`。要是 `application/octet-stream`，
浏览器会把整张样式表丢掉，课件里的中文字体就用不上。

### 4. 视频能不能拖进度条（可选）

```bash
curl -r 100-999 -I https://codebn.cn/leqixiang/courseware/lab-course-phyc140-air-table/assets/video/perfectly%20elastic.mp4
```

应该返回 `206`，并且带 `Content-Range` 头。

### 5. 有没有压缩（可选）

```bash
curl -I -H "Accept-Encoding: gzip" https://codebn.cn/leqixiang/catalog.json
```

应该有 `Content-Encoding: gzip`。

目录清单有一兆多，样式表和脚本也不少，压缩之后小很多。
视频和图片本来就是压过的，nginx 不会再去压它们，
拖进度条也不受影响（还是 `206`，带 `Content-Range`）。

### 6. 字体是不是本地自带的（可选）

课件里用到的中文字体全部放在课件库自己的目录里，不会去外网取。
打开浏览器开发者工具的网络面板，刷新任意一门课件，
请求里不应该出现 `fonts.gstatic.com` 这样的站外地址。

## 四、为什么这么配

### 1. `proxy_hide_header Content-Disposition`

这个桶开了「强制下载」，每个对象回来都带着
`Content-Disposition: attachment` 和 `x-oss-force-download: true`。
不摘掉的话，浏览器打开 `index.html` 会变成下载一个 html 文件，
页面根本显示不出来。摘掉之后网页才是网页。

课件自己的「下载」按钮不受影响——那个下载是浏览器在页面里打包的，
不经过这个头。

### 2. 缓存不用另写

每个对象在上传的时候就把缓存规矩定好了（页面和清单 5 分钟，素材和脚本 30 天），
转发的时候原样带回来，nginx 这边不用再写 `expires`。

### 3. 为什么开了 gzip

`gzip_proxied any` 是必须写的。nginx 默认不压缩转发回来的东西，
不写这一句，前面几行都不起作用。

`gzip_types` 只列了 `application/json` 和 `text/javascript`：
nginx 自带的默认列表里已经有 `text/html`、`text/css`、`text/plain`
这些，写上去会报「duplicate MIME type」的警告。
`application/json` 是默认列表里没有的，而目录清单正好是这个类型，
所以要自己补上。

### 4. 404 的样子

取不到的文件，默认会把对象存储自己的报错显示出来。要改成一句干净的话，
把下面这几行加到 `location ^~ /leqixiang/ { ... }` 里面（把行首的 `#` 去掉）：

```nginx
    proxy_intercept_errors on;
    error_page 404 = @leqixiang_notfound;
    location @leqixiang_notfound {
        return 404 "课件文件不存在\n";
    }
```

## 五、不用对象存储的另一种做法

如果不想用对象存储，也可以把课件包解开，直接放到官网目录下面：

1. 把 `deploy-pkg` 里的压缩包解开；
2. 解出来的整个目录放到 `/www/wwwroot/codebn.cn/leqixiang/`；
3. nginx 里不加上面那三段，改成：

```nginx
    location = /leqixiang {
        return 301 /leqixiang/;
    }
    location ^~ /leqixiang/ {
        root /www/wwwroot/codebn.cn;
        try_files $uri $uri/ =404;
    }
```

这条路简单，但是服务器要放 3.7 GB，而且以后每次更新都要重新传一遍。
对象存储这条路服务器上一个字节都不用放，更新也只改桶里的文件。

---

## 六、出问题怎么退回去

把 nginx 配置里我们加的那三段删掉，保存重载，官网立刻恢复原样，
课件库还在对象存储上，一点没动。

## 八、已知的取舍

**下载压缩包解开后，课件里的中文字体会退回系统字体。**

课件正文引用的样式表在 `shared/` 目录里，是所有课件共用的一份。
浏览器在页面上「下载」时打出来的压缩包，只装课件自己目录下的东西，
装不上 `shared/` 里的那份样式表。课件的功能一点不受影响，
只是解出来的 HTML 看着跟网页版略有差别。

要彻底解决，得给每一门课单独生成一份带完整样式的 HTML，
1450 门课多出来 50 MB 重复文件，换来的是一个看起来更齐整的压缩包。
这次没有做，因为收益小、体积代价大，改动还有把已经验过的课件弄坏的风险。
